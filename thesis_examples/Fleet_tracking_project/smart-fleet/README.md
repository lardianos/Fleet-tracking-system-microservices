# Ιστορικό θέσεων — ενσωμάτωση σε Admin και Fleet Manager

Το πακέτο βασίζεται στα App.tsx, AdminDashboard.tsx, App.css, LiveMap.tsx και Position.ts που ανέβασες στις 21/10/2026. Περιέχει τις αλλαγές για την οθόνη ιστορικού και ένα πρόσθετο endpoint για τις αναθέσεις του επιλεγμένου οχήματος.

## 1. Νέα αρχεία frontend

Αντέγραψε από το πακέτο τα παρακάτω στον αντίστοιχο φάκελο του project:

| Αρχείο | Ρόλος |
|---|---|
| `frontend/src/types/PositionHistory.ts` | Τύποι ιστορικών θέσεων, cursor και διαστημάτων αναθέσεων |
| `frontend/src/services/positionHistory.ts` | Αιτήματα στο Gateway, όλες οι σελίδες και συσχέτιση με audit |
| `frontend/src/components/PositionHistory.tsx` | Κοινή οθόνη αναζήτησης, πίνακας και επιλογή καταγεγραμμένης θέσης |
| `frontend/src/components/PositionHistoryMap.tsx` | Χάρτης ιστορικού με χωριστές γραμμές ανά όχημα, ανάθεση και αλλαγή IMEI |

Ο ιστορικός τύπος είναι χωριστός από το live `Position`, επειδή το TimescaleDB δεν επιστρέφει πεδία όπως `codec_id`, `priority` και `io_elements`.

## 2. Ενσωμάτωση στα υπάρχοντα αρχεία

Το πακέτο περιέχει ολόκληρα τα ενημερωμένα `App.tsx`, `AdminDashboard.tsx` και `App.css` για αντιγραφή. Αν προτιμάς να κάνεις μόνο τις προσθήκες με το χέρι, αυτές είναι ακριβώς οι αλλαγές:

### App.tsx

Στα imports:

```tsx
import PositionHistory from "./components/PositionHistory";
```

Στο μενού **Fleet Manager**, κάτω από το Fleet Drivers:

```tsx
                           <button type="button" aria-pressed={activeManagerSection === "history"} onClick={() => setActiveManagerSection("history")}> Position History </button>
```

Στο περιεχόμενο του Fleet Manager, ακριβώς πριν από το υπάρχον σχόλιο «Το tracking παραμένει ορατό ανεξάρτητα από την επιλεγμένη ενότητα»:

```tsx
                           {activeManagerSection === "history" && (<PositionHistory vehicles={fleetVehicles} drivers={fleetDrivers}/>)}
```

### AdminDashboard.tsx

Στα imports:

```tsx
import PositionHistory from "./PositionHistory";
```

Στο μενού του Admin, κάτω από το Vehicles:

```tsx
                    <button type="button" aria-pressed={activeAdminSection === "history"} onClick={() => setActiveAdminSection("history")}> Position History </button>
```

Ακριβώς κάτω από το `<h2>Admin Dashboard</h2>`:

```tsx
                    {activeAdminSection === "history" && (<PositionHistory vehicles={vehicles} drivers={drivers}/>)}
```

### App.css

Πρόσθεσε στο τέλος όλο το περιεχόμενο του αρχείου `history.css` που βρίσκεται στη ρίζα του πακέτου. Το ενημερωμένο `frontend/src/App.css` περιέχει ήδη αυτή την προσθήκη.

Επίλεξε είτε την αντιγραφή των έτοιμων ενημερωμένων αρχείων είτε τις παραπάνω χειροκίνητες προσθήκες, για να μη διπλασιάσεις imports ή στοιχεία στην οθόνη.

## 3. Ένα πρόσθετο endpoint στο Gateway

Για την αναζήτηση με όχημα, η οθόνη χρειάζεται τις αλλαγές οδηγού ώστε να δείχνει ποιος είχε την ανάθεση κάθε περίοδο. Το υφιστάμενο endpoint οδηγού δεν επιστρέφει αυτό το σύνολο στοιχείων για ένα επιλεγμένο όχημα.

Άνοιξε το `backend/vehicle_assignment_audit.py` του πακέτου και πρόσθεσε ολόκληρο το περιεχόμενό του στο τέλος του **υπάρχοντος** `api-gateway/src/main.py`.

Το αρχείο είναι απόσπασμα για προσθήκη στο main.py· δεν το αντιγράφεις ως ανεξάρτητο service ή module. Χρησιμοποιεί τα ήδη υπάρχοντα `quote`, `httpx`, `Depends`, `validate_access_token`, `role_checker`, `get_authenticated_fleet_manager_fleet_id` και `request_position_history_json`.

Το νέο endpoint είναι:

```text
GET /api/v1/vehicles/{vehicle_id}/assignment-audit
```

Εφαρμόζει τους ίδιους περιορισμούς με το ιστορικό θέσεων: Admin σε όλα, Fleet Manager μόνο σε όχημα που ανήκει σήμερα στο fleet του, Driver χωρίς πρόσβαση. Επιστρέφει μόνο τα IDs, τις χρονικές στιγμές και τις αλλαγές `driver_id` του audit. Δεν χρειάζεται αλλαγή σε Fleet API, Processor, βάση ή Compose σε αυτό το βήμα.

Κάνε rebuild του Gateway από τον φάκελο του Compose:

```powershell
docker compose up -d --build api-gateway
```

## 5. Δοκιμή χρήσης

### Admin — όχημα

1. Άνοιξε **Position History** από το μενού του Admin.
2. Επίλεξε **Vehicle** και **XNR-4885**.
3. Βάλε αρχή **19/10/2026, 14:00** και τέλος **19/10/2026, 22:00**, εφόσον ο browser χρησιμοποιεί ώρα Ελλάδας. Αντιστοιχούν στο διάστημα UTC 11:00–19:00 που ήδη ελέγξαμε.
4. Πάτησε **Show History**. Θα γίνουν αυτόματα όσα αιτήματα σελίδων χρειάζονται μέχρι `has_more: false`.
5. Έλεγξε τον αριθμό θέσεων, τον πίνακα αναθέσεων και τον χάρτη. Ο ολισθητής επιλέγει πραγματική καταγεγραμμένη θέση και δείχνει ώρα, όχημα, ανατεθειμένο οδηγό, ταχύτητα, IMEI και συντεταγμένες.

### Admin — οδηγός

1. Άλλαξε σε **Driver** και επίλεξε τον `drv-001`.
2. Κράτησε το ίδιο διάστημα και πάτησε **Show History**.
3. Οι αναθέσεις για XNR-4885 και NIT-4832 εμφανίζονται χωριστά. Ένα όχημα μπορεί να έχει μηδέν θέσεις, παρότι είχε ανάθεση.
4. Ανακτώνται θέσεις μόνο μέσα στα διαστήματα ανάθεσης που επέστρεψε το Fleet API. Κάθε διάστημα ολοκληρώνει όλες τις σελίδες του.

### Fleet Manager

Άνοιξε την ίδια ενότητα από το μενού του Manager. Οι επιλογές προέρχονται από τις υπάρχουσες λίστες του fleet του. Το Gateway επανελέγχει τα δικαιώματα σε κάθε αίτημα θέσεων ή audit.

### Ακύρωση και νέες αναζητήσεις

Κατά τη φόρτωση εμφανίζεται αριθμός θέσεων και κουμπί **Cancel**. Η αλλαγή ενότητας ακυρώνει επίσης τα αιτήματα. Αν αποτύχει κάποια σελίδα, εμφανίζεται σφάλμα αντί για αποτέλεσμα που μοιάζει ολοκληρωμένο αλλά είναι ελλιπές.

Το **Last 8 Hours** συμπληρώνει το χρονικό διάστημα. Μετά πατάς **Show History**. Οι ώρες εισόδου και εμφάνισης ακολουθούν τη ζώνη ώρας του browser· το API λαμβάνει UTC.

## Συμπεριφορά audit και χάρτη

- «Assigned driver» σημαίνει καταγεγραμμένη ανάθεση, όχι επιβεβαίωση του πραγματικού προσώπου στο τιμόνι.
- Αν λείπει γνωστή αρχική κατάσταση πριν από την πρώτη καταγραφή του audit, εμφανίζεται **Unknown (no assignment audit)**. Αν το audit καταγράφει αποδέσμευση, το επόμενο διάστημα εμφανίζεται ως **Unassigned**.
- Ο χάρτης συνδέει τα καταγεγραμμένα σημεία με γραμμές. Δεν κάνει αντιστοίχιση στο οδικό δίκτυο ούτε ανίχνευση trips. Μεγάλα κενά τηλεμετρίας μέσα στην ίδια ανάθεση εξακολουθούν να συνδέονται με γραμμή.
- Διαφορετικά οχήματα, διαστήματα αναθέσεων και διαδοχικές αλλαγές IMEI εμφανίζονται ως χωριστές γραμμές. Ακόμη και μία μεμονωμένη θέση εμφανίζεται ως σημείο.
- Οι λίστες επιλογών περιέχουν τις υπάρχουσες οντότητες που έχουν φορτώσει τα dashboards. Δεν προστίθεται επιλογέας διαγραμμένων οχημάτων ή οδηγών σε αυτή την οθόνη.

## Έλεγχοι που έγιναν εδώ

- Έλεγχος σύνταξης TypeScript/JSX στα νέα και στα τροποποιημένα αρχεία.
- Αυστηρός έλεγχος τύπων στους νέους τύπους και στη λογική αιτημάτων ιστορικού.
- Δοκιμές αλλαγών ανάθεσης, UTC χωρίς offset στο audit, άγνωστης ανάθεσης, αποκλεισμού του τέλους του διαστήματος, πολλαπλών σελίδων, μεταφοράς cursor, επανάληψης cursor, σφάλματος 403 και ακύρωσης.
- Έλεγχος Python σύνταξης και δοκιμές του νέου endpoint με προσομοιωμένα services για Admin, επιτρεπόμενο Manager, Manager άλλου fleet και Driver.

Δεν έγινε πραγματική εκτέλεση στον browser ή σύνδεση με τα containers σου. Ο πλήρης έλεγχος του frontend με TypeScript δεν ολοκληρώθηκε εδώ, επειδή στο διαθέσιμο αντίγραφο του node_modules λείπουν Leaflet/React Leaflet. Γι' αυτό περιλαμβάνεται το `npm run build` και ο παραπάνω έλεγχος στη δική σου εγκατάσταση.
